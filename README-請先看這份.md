因為你問到「換版會不會影響目前官網的收錄」，這次也一併處理了：

- **`sitemap.xml` 自動產生**：舊網站目前沒有這個檔案，新版加了 `jekyll-sitemap` 這個外掛，會自動幫全站產生 sitemap，讓 Google 更快發現新的頁面結構。

- **網域本身的信任度不受影響**：`enchiang.com` 這個網域從註冊、被連結、被收錄的歷史都是連續的，不會因為换了程式架構或換了 repo 就重置——真正需要留意的只有上面這幾個「網址結構」層面的細節，處理好之後，換版本身不會傷到網域的基礎。

老實說一句：**任何網站做較大幅度的結構調整，短期（通常是幾天到幾週）都可能看到 Google 收錄資料有一點小波動**，這是 Google 需要重新爬取、重新判斷新結構的正常現象，只要新網址結構清楚、有轉址、內容沒有變差，通常會自己回穩，不會是永久性的損失。真正切換的那天，建議你（或我陪你一起）到 Google Search Console 提交一次新的 sitemap，會讓 Google 更快跟上新的頁面結構。

## 怎麼安全測試（第一版保留不動，第二版另外開一個 repo）

這正是你要的「兩個版本並存、最後再選要上架哪一個」的做法。原理是：`enchiang.com` 這個網域，現在是接在 `enchiang99/en-chiang-site`（第一版）這個 repo 上，一個網域同時間只能接一個 repo。所以「保留第一版、同時測試第二版」的做法，就是**先把第二版放在另一個全新的 repo**，兩個 repo 互不影響、都會一直存在，之後要上架哪一版，只是「把網域改接去哪個 repo」的設定問題，不會刪掉、也不會動到另一版。

1. 在 GitHub 上開一個**新的 repo**（不要用 `en-chiang-site` 那個，第一版完全不動），例如叫 `en-chiang-site-v2`。
2. 把這個資料夾（除了這份 README）整個上傳進去。
3. 到 repo 的 Settings → Pages，把 GitHub Pages 打開（Branch 選 `main`）。
4. 打開 `_config.yml`，把 `baseurl: ""` 改成 `baseurl: "/en-chiang-site-v2"`（跟你的 repo 名稱一致，前面要有 `/`）——這一步是因為沒有掛自訂網域的測試網址，長相會是 `https://你的帳號.github.io/repo名稱/`，多了一段路徑，這樣站內的連結（選單、返回首頁之類）才會對得上。**這個 `baseurl` 只是測試階段用，等正式要上架時要記得改回空字串。**
5. 等個一兩分鐘，會得到一個像 `https://enchiang99.github.io/en-chiang-site-v2/` 的網址，把這個網址給我，我可以直接幫你確認頁面有沒有正常長出來、跟原本網站的風格是不是一致。
6. 這階段有一個小小的已知限制：目前搬過來的舊照片都是完整網址（`https://enchiang.com/images/...`），在測試網址上會正常顯示；但如果你在**測試期間**透過後台「新增照片」上傳全新的圖，因為子路徑的關係，那幾張新圖在測試網址上暫時會顯示不出來——這不是壞掉，等正式上架（用自己的網域或搬進第一版 repo）之後就會自動恢復正常，純粹是測試網址本身的限制，不用特別處理。

**最後要「選要上架哪一版」的時候**，有兩種做法，都很安全：

- **接網域**：到 Cloudflare／你的網域註冊商，把 `enchiang.com` 的 DNS 設定改成指向第二版的 repo（GitHub Pages 那邊的 Settings → Pages → Custom domain 填上 `enchiang.com`），第一版 repo 保持原樣不動，網域不再指向它而已，內容還在，隨時可以切回去。
- 或是等你確定要長期採用第二版了，我再幫你把這批檔案覆蓋進第一版 repo（`en-chiang-site`），這樣就只維護一個 repo——但不急著現在做，先測試、確定沒問題再說。
